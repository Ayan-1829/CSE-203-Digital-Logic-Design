Memory & Error Correction

How memory is organised, decoded and expanded, and how errors are detected and corrected.

Before we start

Why this matters

When Voyager 1 beams a photo home from over 15 billion miles away and cosmic rays casually flip a few of its bits mid-flight, how does the picture still turn out fine?

Error-correcting codes let the receiver catch a flipped bit and quietly fix it, no “can you resend that?” across a round trip that takes over a day one-way. It's the same superpower that lets a scratched CD keep playing and your Wi-Fi survive the microwave reheating last night's leftovers. It all starts with memory organised into tidy, addressable rows and columns.

Concept 1 of 4

Memory organisation

Memory stores binary words at numbered addresses. It is described as words × bits per word: 1K × 8 means 1024 words of 8 bits. n address lines select 2n locations. Data lines carry the word to or from memory.

  • Read: apply the address, enable the memory, activate read, and the word appears on the data lines.
  • Write: apply address and data, enable the memory, activate write, and the word is stored.
capacity = 2ⁿ words × m bits
10 address lines, 8 data lines: 1024 × 8 = 8192 bits = 1 KB

Concept 2 of 4

RAM: SRAM and DRAM

Random-access memory can be read and written at any address in the same time. SRAM uses bistable cells, needs no refresh and is fast, but its cost and size rule it out as a computer's main memory — it is used for the much smaller cache instead. DRAM stores charge in a capacitor, so it must be refreshed periodically, but it draws less power and packs more bits per chip, which is why it does the job of main memory. Both lose their contents without power.

Concept 3 of 4

Address decoding and expansion

A decoder turns address bits into a select line for a location or a chip. A chip select input enables only the chip being addressed. Many chips share one tri-state data bus, and only the selected chip drives it.

  • Word expansion adds locations: extra high address bits feed a decoder that drives the chip selects.
  • Bit expansion widens the word: chips share the address lines and their data lines side by side (two 4-bit chips make an 8-bit word).

A memory map lists which address range belongs to which device.

Concept 4 of 4

Error detection and correction

A parity bit detects any single-bit error but cannot say which bit. A Hamming code places check bits at the power-of-two positions (1, 2, 4, …). Recomputing the checks after a read gives a syndrome, which is the position of a single wrong bit, so it can be flipped back. Adding one overall parity bit gives SEC-DED: single-error correction and double-error detection.

Worked example 1

How many locations can 12 address lines select, and what is the capacity of a 2K × 8 memory?
Show the solution
  1. 212 = 4096 locations.
  2. 2K × 8 = 2048 × 8 = 16384 bits = 2 KB.

Worked example 2 of 3

Worked example 2

Build a 4K × 8 memory from 1K × 8 chips.
Show the solution
  1. Chips needed: 4K / 1K = 4.
  2. Address lines: 12. The low 10 go to every chip. The top 2 feed a 2-to-4 decoder that drives the four chip selects.

Worked example 3 of 3

Worked example 3

A 12-bit Hamming-coded word is 001110010100. Add an overall parity bit P13 (even parity, the XOR of the other 12 bits) to turn it into a 13-bit SEC-DED word. Then, if a later read gives a non-zero syndrome C and overall parity P = 1, what should the receiver do?
Show the solution
  1. XOR the 12 bits: 0⊕0⊕1⊕1⊕1⊕0⊕0⊕1⊕0⊕1⊕0⊕0 = 1, so P13 = 1.
  2. 13-bit SEC-DED word: 001110010100 with P13 appended = 0011100101001.
  3. C ≠ 0 and P = 1 means a single bit is wrong. Look up C in the syndrome table and flip that bit — the error is correctable.
Result 0011100101001; a later (C≠0, P=1) reading is corrected automatically.

Summary

  • Word expansion adds locations, bit expansion adds width.
  • SEC-DED corrects one error and detects two.
