Before we start

Why this matters

How does a calculator add 127 + 1 and confidently tell you the answer is −128?

That's not the calculator having a stroke — it's called overflow, and a real version of this exact bug once sent an actual rocket (Ariane 5) into an actual meltdown seconds after launch. Underneath every calculator, cash register and CPU is a circuit that only ever adds, subtracts and compares — no fingers, no muttering “carry the one” under its breath. Let's build one that behaves.

Concept

Combinational circuits

Outputs depend only on present inputs. There is no memory. Design procedure: read the specification, list inputs and outputs, write the truth table, derive expressions, simplify (Boolean algebra or K-map), implement, verify. Analysis runs the other way: label gate outputs, write expressions, combine, and check with a truth table.

Half adder

Half adder

Adding two bits by hand only has four cases: 0+0=0, 0+1=1, 1+0=1, and 1+1=10 — write down 0 and carry a 1 to the next column. A half adder is the circuit that does exactly this for a single bit: it takes A and B and produces two outputs, a sum bit and a carry bit. It has no carry-in of its own, which is why it's called “half”.

Full adder

Full adder

A full adder extends the half adder with a third input, Cin — the carry arriving from the previous column. That extra input is what lets full adders be chained together into a multi-bit adder. It can be built from two half adders and an OR gate: the first half adder adds A and B; the second adds that sum to Cin; the two carry outputs are ORed to give Cout.

Deriving Sum from the truth table's 1-rows: S = A′B′Cin + A′BCin′ + AB′Cin′ + ABCin. Group the pairs around A: A′(B′Cin + BCin′) + A(B′Cin′ + BCin) = A′(B⊕Cin) + A(B⊕Cin)′ = A ⊕ B ⊕ Cin.
Deriving Cout the same way: Cout = A′BCin + AB′Cin + ABCin′ + ABCin. Group around Cin, then pull AB out of the remaining pair: Cin(A′B + AB′) + AB(Cin′ + Cin) = Cin(A⊕B) + AB.

Subtractor

Half and full subtractor

Subtraction works the same way as addition but borrows instead of carrying: a half subtractor computes A − B for one bit, assuming no borrow-in. A full subtractor adds a borrow-in Bin, which is what's needed when chaining subtractors across multiple bits, just like Cin does for adders.

Deriving Difference from the 1-rows: D = A′B′Bin + A′BBin′ + AB′Bin′ + ABBin — the same pattern as the full adder's Sum: A′(B⊕Bin) + A(B⊕Bin)′ = A ⊕ B ⊕ Bin.
Deriving Bout: Bout = A′B′Bin + A′BBin′ + A′BBin + ABBin. Group the 1st and 2nd terms around A′, and the 3rd and 4th around BBin: A′(B′Bin + BBin′) + BBin(A′ + A) = A′(B⊕Bin) + BBin — which expands to the same A′B + A′Bin + B·Bin shown above.

4-bit adder

4-bit ripple-carry adder

Chaining n full adders, with each stage's carry-out feeding the next stage's carry-in, gives an n-bit ripple-carry adder. Drawn as a block diagram, each full adder (FA) is a box that takes Ai, Bi and a carry-in and produces Si and a carry-out — the diagram below chains four of them into a 4-bit adder. The name comes from the carry needing to “ripple” through every stage before the final sum is ready, so the worst-case delay grows with the number of bits.

Adder-subtractor

4-bit adder/subtractor

Hardware usually subtracts with 2’s complement: A − B = A + B′ + 1. Put an XOR gate on each bit of B, controlled by a single mode signal M, and feed M into the carry-in of the first stage. Each XOR acts as a controllable NOT: with its other input tied to M, it passes B through unchanged when M = 0 and complements it when M = 1. The same 4-bit adder block then does both jobs.

M = 0: each XOR passes B through unchanged, Cin = 0 → S = A + B
M = 1: each XOR complements B, Cin = 1 → S = A + B′ + 1 = A − B

For signed numbers, overflow occurs when the carry into the MSB differs from the carry out of the MSB.

Magnitude comparator

1-bit magnitude comparator

A magnitude comparator outputs three signals: A>B, A=B and A<B. For multi-bit numbers, compare from the most significant bit down — the first pair that differs decides the result, and equal bits pass the decision down to the next pair. These blocks combine with multiplexers and logic gates to form an ALU.

Equation and circuit

1-bit magnitude comparator

A>B: G = AB′
A=B: E = (A ⊕ B)′ = A XNOR B
A<B: L = A′B

E isn't just asserted — it falls out of the other two. Since G and L can never both be true, E is their combined complement: (A>B)+(A<B) = AB′+A′B, and by De Morgan, ((A>B)+(A<B))′ = (AB′)′(A′B)′ = (A′+B)(A+B′) = AB+A′B′, which is exactly A XNOR B — confirming E = (A ⊕ B)′.

Magnitude comparator

Multi-bit magnitude comparator

The 1-bit comparator is the base case. Wider comparators are built with exactly the MSB-down rule already mentioned: compare the top bits first, and only look at the next pair down if the top bits tie. Working through a 2-bit comparator (A1A0 vs B1B0) with a K-map gives:

A>B = A1B1′ + A1A0B0′ + B1′A0B0′
A<B = A1′B1 + A1′A0′B0 + B1A0′B0
A=B = (A0 ⊕ B0)′·(A1 ⊕ B1)′

Each term reads as a tie-break: A1B1′ fires when the top bit alone already decides it; A1A0B0′ fires only when the top bits tie (implicitly, since it's ANDed with the top-bit-decides terms in the full sum) and the next bit decides it instead. That same “tie, so fall through to the next stage” pattern is how fixed-width comparator ICs (e.g. the 74LS85 4-bit magnitude comparator) are chained to compare wider numbers: each chip exposes cascading inputs IA>B, IA=B and IA<B, and the equality/inequality outputs of the lower-order chip feed the higher-order chip's cascading inputs, so a tie at one stage falls through to the next. The least-significant stage's cascading inputs are simply tied to the “start out equal” default (IA>B = 0, IA=B = 1, IA<B = 0).

BCD adder

BCD adder

A BCD adder is a 4-bit binary adder followed by correction logic. Each BCD digit only uses codes 0000–1001 (0–9), so the largest possible sum is 9 + 9 + 1 = 19 — codes 1010–1111 never appear in valid BCD. Whenever the 4-bit sum exceeds 9 (or produces a carry), add 0110 (6) to skip over the six unused codes, producing the correct BCD digit plus a carry into the next decimal digit.

Worked example 2

Compute 0110 − 0011 with 2’s complement.
Show the solution
  1. Invert B: 1100, add 1: 1101.
  2. 0110 + 1101 = 1 0011.
  3. Discard the carry: 0011 = 3.

Worked example 3 of 5

Worked example 3

Add 7 + 8 in BCD.
Show the solution
  1. 0111 + 1000 = 1111 (greater than 1001).
  2. Add 0110: 1111 + 0110 = 1 0101.
  3. 0001 0101 = 15.

Worked example 4 of 5

Worked example 4

Compare A = 0110 and B = 0101 using the MSB-down rule.
Show the solution
  1. Bit 3: A=0, B=0 — tie, move to the next bit down.
  2. Bit 2: A=1, B=1 — tie, move to the next bit down.
  3. Bit 1: A=1, B=0 — they differ, and A's bit is the larger one.
The first pair that differs, scanning from the MSB, decides it: A > B (6 > 5). Bit 0 is never even examined.

Worked example 5 of 5

Worked example 5

Add the two-digit BCD numbers 47 + 38, correcting each decimal digit and carrying into the next.
Show the solution
  1. Units digit: 0111 (7) + 1000 (8) = 1111 (15), which is > 9, so add 0110: 1111 + 0110 = 1 0101 — units digit 0101 (5), carry 1 into the tens digit.
  2. Tens digit: 0100 (4) + 0011 (3) + carry-in 1 = 1000 (8), which is ≤ 9, so no correction is needed — tens digit 1000 (8).
Result 1000 0101 = 85.

Summary

Summary

  • Half adder: S = A⊕B, C = AB. Full adder adds a carry-in.
  • Ripple-carry is simple but slow for wide words.
  • A − B = A + B′ + 1. XOR gates plus carry-in make an adder-subtractor.
  • Signed overflow: carry into MSB ≠ carry out of MSB.
  • BCD correction: add 0110 when the sum exceeds 9 or carries.
